## 1. 시스템 개요

### 기술 스택

| 구분 | 기술 |
|------|------|
| **프론트엔드** | Next.js 16, React, TailwindCSS, TanStack Query |
| **백엔드** | Express.js, TypeScript |
| **데이터베이스** | MongoDB (Mongoose) |
| **외부 API** | 한국투자증권(KIS), 네이버 DataLab, 네이버 금융 |

### 주요 기능

- **주도주 분석**: 5가지 지표로 종목별 "핫함 점수" 산출
- **거래대금 TOP**: 상승 종목 중 거래대금 상위 종목
- **주도섹터**: 테마별 종합 점수 랭킹
- **일별 기록**: 캘린더로 날짜별 주도테마 조회
- **테마 상세**: 테마별 종목 시세 + 뉴스 + 차트

## 2. 서버 시작 흐름

```
서버 시작 (npm run dev)
    │
    ├── 1. 환경 변수 로드 (.env)

    │       ├── KIS_APP_KEY / KIS_APP_SECRET

    │
    └── 4. 스케줄러 시작

            ├── 🕷️ 뉴스 크롤링 ──────── 10초마다
```

## 4. 핵심 서비스 상세

### 4.1 themePriceCache.ts (주가 캐싱 서비스)

```typescript
// 위치: apps/server/src/services/themePriceCache.ts

역할: KIS API로 전체 종목 주가를 주기적으로 조회하여 메모리에 캐싱

실행 주기: 5분마다 자동 실행
대상: 262개 테마, 654개 고유 종목

캐싱 데이터:
  • stockCode    - 종목코드 (6자리)
  • stockName    - 종목명
  • currentPrice - 현재가
  • changeRate   - 등락률 (%)
  • changePrice  - 전일대비
  • volume       - 거래량
  • tradingValue - 거래대금

사용처:
  • 테마 상세 페이지 종목 시세
  • 주도섹터 계산
  • 거래대금 TOP 조회
  • 핫함 점수 기초 데이터
```

### 4.2 hotnessService.ts (핫함 점수 서비스)

```typescript
// 위치: apps/server/src/services/hotnessService.ts

역할: 종목별 "핫함 점수" 계산 (100점 만점)

점수 구성:
┌─────────────────────────────────────────────────────────┐
│  지표           │ 배점  │ 데이터 소스                    │
├─────────────────────────────────────────────────────────┤
│  거래량 급증     │ 25점  │ KIS API (전일 대비)            │
│  검색량 급증     │ 25점  │ 네이버 DataLab API             │
│  뉴스 노출       │ 20점  │ MongoDB News 매칭              │
│  수급 (외인/기관) │ 20점  │ KIS API (순매수)              │
│  등락률          │ 10점  │ themePriceCache               │
├─────────────────────────────────────────────────────────┤
│  총점           │ 100점 │                                │
└─────────────────────────────────────────────────────────┘

등급 기준:
  • HOT    : 70점 이상  🔥
  • WARM   : 50~69점   🌡️
  • NORMAL : 30~49점   😐
  • COOL   : 15~29점   ❄️
  • COLD   : 0~14점    🥶

캐시: 5분 TTL (네이버 API 호출 절약)

필터: 등락률 4% 이상 종목만 계산 대상
```

### 4.3 crawler.ts (뉴스 크롤링 서비스)

```typescript
// 위치: apps/server/src/services/crawler.ts

역할: 네이버 금융 뉴스 자동 크롤링

실행 주기: 10초마다
크롤링 대상: https://finance.naver.com (증권 뉴스)

수집 과정:
  1. 뉴스 리스트 페이지 접근
  2. 상위 5개 뉴스 링크 추출
  3. 각 뉴스 상세 페이지 방문
  4. title, press, summary, link 추출
  5. 중복 체크 후 MongoDB 저장

중복 방지: lastNewsLinks (Set)로 이미 수집한 링크 관리
```

### 4.4 leadingStockService.ts (주도주/주도섹터 서비스)

```typescript
// 위치: apps/server/src/services/leadingStockService.ts

역할: 주도섹터 계산 + 일별 기록 저장

주도섹터 점수 계산:
  점수 = (평균 상승률 × 0.5) + (총 거래대금 순위 × 0.5)

제공 데이터:
  • themeName        - 테마명
  • avgChangeRate    - 평균 등락률
  • totalTradingValue - 총 거래대금
  • topStock         - 대장주 (등락률 1위)
  • topStockRate     - 대장주 등락률

일별 저장:
  • 실행 주기: 30분마다
  • 저장 대상: TOP 10 테마
  • 보관 기간: 90일 (자동 삭제)
```

### 4.5 naverDataLab.ts (네이버 검색량 API)

```typescript
// 위치: apps/server/src/services/naverDataLab.ts

역할: 네이버 DataLab API로 검색량 트렌드 조회

API 제한:
  • 일일 1,000회
  • 배치당 최대 5개 키워드
  • 배치 간 1초 딜레이 필요

검색량 급증률 계산:
  급증률 = (최근 1일 평균 - 최근 7일 평균) / 최근 7일 평균 × 100

점수 환산 (0~25점):
  • 300%+ 급증 → 25점
  • 200%+ 급증 → 20점
  • 100%+ 급증 → 15점
  • 50%+ 급증  → 10점
  • 0%+ 급증   → 5점
  • 감소       → 0점

캐시:
  • 개별 키워드: 1시간 TTL
  • 핫함 점수 전체: 5분 TTL
```

## 5. 외부 API

### 5.1 한국투자증권 (KIS) API

```
용도: 실시간 주가, 거래량, 수급 데이터

인증: OAuth (APP_KEY + APP_SECRET → Access Token)
토큰 유효기간: 24시간 (자동 갱신)

사용 엔드포인트:
  • /uapi/domestic-stock/v1/quotations/inquire-price    - 현재가
  • /uapi/domestic-stock/v1/quotations/inquire-daily-price - 일별 시세

호출 제한: 초당 10회
현재 사용량: 5분마다 654종목 (약 70초 소요)
```

### 5.2 네이버 DataLab API

```
용도: 검색어 트렌드 (검색량 급증 감지)

인증: Client ID + Client Secret (헤더)
엔드포인트: https://openapi.naver.com/v1/datalab/search

호출 제한: 1,000회/일
현재 사용량: ~288회/일 (5분 캐시 적용)

요청 제한:
  • 한 번에 최대 5개 키워드
  • 배치 간 1초 딜레이 권장
```

### 5.3 네이버 금융 (크롤링)

```
용도: 증권 뉴스 수집

대상 URL: https://finance.naver.com
수집 주기: 10초마다
수집 개수: 상위 5개 뉴스

주의: 공식 API 아님, 크롤링 방식
```

## 6. 데이터베이스 스키마

### 6.1 News (뉴스)

```javascript
{
  title: String,        // 뉴스 제목
  link: String,         // 원문 링크 (unique)
  press: String,        // 언론사
  summary: String,      // 요약/본문 일부
  publishedAt: Date,    // 발행일
  crawledAt: Date,      // 크롤링 시간
  themes: [String],     // 관련 테마 (선택)
}

// 인덱스
- link: unique
- publishedAt: -1
- themes: 1
```

### 6.2 Theme (테마)

```javascript
{
  name: String,         // 테마명 (unique)
  stocks: [String],     // 관련 종목 (종목명 배열)
  keywords: [String],   // 키워드
  source: String,       // 출처 ('naver')
  isCustom: Boolean,    // 커스텀 여부 (false)
  createdAt: Date,
  updatedAt: Date,
}

// 인덱스
- name: unique
- source: 1
```

### 6.3 ThemeHistory (테마 히스토리)

```javascript
{
  themeName: String,    // 테마명
  timestamp: Date,      // 기록 시간
  avgChangeRate: Number,// 평균 등락률
  topStock: String,     // 대장주
  topStockRate: Number, // 대장주 등락률
}

// 인덱스
- themeName: 1, timestamp: -1
- timestamp: 1 (TTL: 30일)
```

### 6.4 DailyLeadingTheme (일별 주도테마)

```javascript
{
  date: Date,           // 날짜 (unique)
  topThemes: [{
    rank: Number,       // 순위 (1~10)
    themeName: String,  // 테마명
    avgChangeRate: Number,
    totalTradingValue: Number,
    topStock: String,   // 대장주
    topStockRate: Number,
  }],
  createdAt: Date,
}

// 인덱스
- date: unique, -1
- date: 1 (TTL: 90일)
```

## 7. API 엔드포인트

### 7.1 뉴스 API (`/api/news`)

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/news` | 전체 뉴스 목록 (페이지네이션) |
| GET | `/api/news/theme/:themeName` | 테마별 뉴스 |

### 7.2 테마 API (`/api/themes`)

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/themes` | 전체 테마 목록 + 메타정보 |
| GET | `/api/themes/:name` | 테마 상세 (종목 시세 포함) |
| GET | `/api/themes/:name/history` | 테마 등락률 히스토리 |

### 7.3 종목 API (`/api/stocks`)

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/stocks/:code` | 종목 현재가 |

### 7.4 주도주 탐색기 API (`/api/leading`)

| 메서드 | 경로 | 설명 | 캐시 |
|--------|------|------|------|
| GET | `/api/leading/hot` | 핫함 점수 TOP 30 | 5분 |
| GET | `/api/leading/stocks` | 거래대금 TOP (4%↑) | - |
| GET | `/api/leading/sectors` | 주도섹터 랭킹 | - |
| GET | `/api/leading/calendar` | 일별 주도테마 | - |
| GET | `/api/leading/calendar/:date` | 특정 날짜 상세 | - |

## 10. 알고리즘 상세

### 10.1 검색량 급증률 알고리즘

#### 데이터 수집 (네이버 DataLab API)

```
요청: "삼성전자" 최근 7일 검색량

응답 예시:
┌──────────────┬────────┐
│    날짜      │ ratio  │  ← 0~100 상대값 (최고점 = 100)
├──────────────┼────────┤
│  1/14 (화)   │   45   │
│  1/15 (수)   │   52   │
│  1/16 (목)   │   48   │
│  1/17 (금)   │   55   │
│  1/18 (토)   │   42   │
│  1/19 (일)   │   38   │
│  1/20 (월)   │   85   │  ← 오늘 (급증!)
└──────────────┴────────┘

※ ratio는 절대 검색량이 아닌 상대값 (해당 기간 최고치 = 100)
```

#### 급증률 계산 공식

```
급증률 = (오늘 ratio - 과거 6일 평균) / 과거 6일 평균 × 100

예시:
  • 오늘 ratio: 85
  • 과거 6일 평균: (45+52+48+55+42+38) / 6 = 46.7

  급증률 = (85 - 46.7) / 46.7 × 100 = 82.0%
```

#### 점수 환산 (0~25점)

| 급증률 | 점수 | 의미 |
|--------|------|------|
| 300% 이상 | 25점 | 폭발적 관심 |
| 200% ~ 299% | 20점 | 매우 높은 관심 |
| 100% ~ 199% | 15점 | 2배 급증 |
| 50% ~ 99% | 10점 | 관심 증가 |
| 0% ~ 49% | 5점 | 평균 수준 |
| 마이너스 | 0점 | 관심 감소 |

#### 실제 예시

```
종목: "에코프로"

네이버 검색 트렌드:
  • 1/14~1/19 평균: 30
  • 1/20 (오늘): 95

급증률: (95 - 30) / 30 × 100 = 216.7%
점수: 20점 (200% 이상)
```

#### 알고리즘 선택 이유

| 특징 | 이유 |
|------|------|
| **7일 기준** | 단기 트렌드 감지 (너무 길면 둔감, 짧으면 노이즈) |
| **상대값 비교** | 절대 검색량은 종목마다 천차만별 |
| **급증률** | "갑자기 관심 증가"를 포착 (주가 급등 선행 지표) |

### 10.2 핫함 점수 알고리즘

#### 점수 구성 (100점 만점)

```
핫함 점수 (100점)
├── 거래량 급증  25점  ← 전일 대비 거래량 증가율
├── 검색량 급증  25점  ← 네이버 DataLab 7일 비교
├── 뉴스 노출    20점  ← 최근 뉴스에서 종목명 언급 횟수
├── 수급        20점  ← 외국인/기관 순매수
└── 등락률      10점  ← 당일 주가 상승률
```

#### 각 지표별 점수 기준

**거래량 급증 (0~25점)**
```
전일 대비 거래량 배수:
  • 5배 이상  → 25점
  • 3배 이상  → 20점
  • 2배 이상  → 15점
  • 1.5배 이상 → 10점
  • 1배 이상  → 5점
  • 감소      → 0점
```

**뉴스 노출 (0~20점)**
```
최근 24시간 뉴스 언급 횟수:
  • 10건 이상 → 20점
  • 7건 이상  → 15점
  • 4건 이상  → 10점
  • 1건 이상  → 5점
  • 0건      → 0점
```

**수급 (0~20점)**
```
외국인 + 기관 순매수:
  • 둘 다 순매수    → 20점
  • 하나만 순매수   → 10점
  • 둘 다 순매도    → 0점
```

**등락률 (0~10점)**
```
당일 등락률:
  • 15% 이상 (상한가 근접) → 10점
  • 10% 이상              → 8점
  • 5% 이상               → 6점
  • 2% 이상               → 4점
  • 0% 이상               → 2점
  • 마이너스              → 0점
```

#### 등급 기준

| 총점 | 등급 | 의미 |
|------|------|------|
| 70점 이상 | 🔥 HOT | 매우 뜨거운 종목 |
| 50~69점 | 🌡️ WARM | 관심 필요 |
| 30~49점 | 😐 NORMAL | 보통 |
| 15~29점 | ❄️ COOL | 관심 낮음 |
| 0~14점 | 🥶 COLD | 소외 종목 |

### 10.3 주도섹터 점수 알고리즘

#### 계산 공식

```
주도섹터 점수 = (평균 상승률 점수 × 0.5) + (거래대금 순위 점수 × 0.5)

평균 상승률: 테마 내 모든 종목의 등락률 평균
거래대금: 테마 내 모든 종목의 거래대금 합계
```

#### 예시

```
테마: "2차전지"
├── 종목 A: +8.5%, 거래대금 500억
├── 종목 B: +6.2%, 거래대금 300억
├── 종목 C: +4.1%, 거래대금 200억
└── 종목 D: +2.3%, 거래대금 100억

평균 상승률: (8.5 + 6.2 + 4.1 + 2.3) / 4 = 5.28%
총 거래대금: 1,100억

→ 상승률 높고 거래대금 많으면 주도섹터 상위 랭크
```
