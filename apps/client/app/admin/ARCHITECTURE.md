# TEBURN 자동매매봇 — 아키텍처

> TEBURN 주도주 분석 데이터를 활용한 국내주식 자동매매 시스템

---

## 전체 흐름

```
TEBURN 서버 (기존)                자동매매봇 (신규)                  외부 서비스
─────────────────               ─────────────────                ─────────────
                                                                
[네이버 금융] ──크롤링──→ 테마/종목 DB                              
[KIS API] ──시세조회──→ 주가 캐시                                  
[네이버 뉴스] ──크롤링──→ 뉴스 DB                                  
                │                                                
        주도주 점수 산출                                           
        (hotnessService)                                         
                │                                                
    /api/leading/hot ──────→ ① 시그널 수신                        
                             (S등급 주도주)                        
                                  │                              
                             ② 기술적 검증 ←──── [KIS API 일봉]   
                             (RSI + MA 필터)                      
                                  │                              
                             ③ 매수 실행 ────→ [KIS 주문 API]     
                                  │                              
                             ④ 포지션 모니터링 ←── [KIS 현재가]    
                             (손절/익절 체크)                      
                                  │                              
                             ⑤ 매도 실행 ────→ [KIS 주문 API]     
                                  │                              
                             ⑥ 알림 발송 ────→ [텔레그램]          
                                  │                              
                             ⑦ 대시보드 ────→ 브라우저 (:3001)     
```

## 1단계: TEBURN 서버 (기존 시스템)

봇이 직접 분석하는 게 아니라, TEBURN이 이미 분석해놓은 결과를 가져다 씁니다.

| 작업 | 주기 | 설명 |
|------|------|------|
| 테마/종목 크롤링 | 1일 1회 | 네이버 금융에서 테마 목록, 구성 종목 수집 |
| 실시간 시세 조회 | 5분 | KIS Open API로 종목별 현재가, 거래대금, 등락률 |
| 뉴스 크롤링 | 10초 | 네이버 증권 뉴스 수집 → 테마/종목 매칭 |
| **주도주 점수 산출** | **5분** | 아래 5개 지표 합산 → 100점 만점 |

### 주도주 점수 체계 (hotnessService.ts)

```
거래대금 (25점)     1000억 이상 = 25점, 500억 = 21점, 300억 = 17점 ...
등락률 (25점)       +20% = 25점, +15% = 21점, +10% = 17점 ...
거래량 급증 (20점)   10배 이상 = 20점, 5배 = 16점, 3배 = 12점 ...
뉴스 노출 (15점)    10건 이상 = 15점, 5건 = 12점, 3건 = 9점 ...
대장주 집중도 (15점)  테마 내 거래대금 점유율 50%+ = 15점 ...
────────────────────────────────────────────────────────
총점 = 100점 만점
```

### 등급 기준

| 등급 | 점수 | 의미 |
|------|------|------|
| **S** | 70점+ | 자금 쏠림 + 모멘텀 + 뉴스 모두 갖춘 핵심 주도주 |
| A | 50~69점 | 강한 모멘텀, 일부 지표 부족 |
| B | 35~49점 | 중간 수준 |
| C | 20~34점 | 약한 모멘텀 |
| D | 20점 미만 | 관심 대상 아님 |

## 2단계: 시그널 수신 (봇 → TEBURN API)

봇이 5분마다 TEBURN 서버의 `/api/leading/hot`을 호출합니다.

```
GET /api/leading/hot
→ HotnessScore[] (주도주 점수 TOP 종목 리스트)
```

### 1차 필터링 (signalProvider.ts)

- **등급 필터**: S등급(70점+) 종목만 통과
- **등락률 범위**: 4% ~ 25% (너무 안 오른 것, 너무 오른 것 제외)
- **거래대금**: 100억 이상 (유동성 확보)
- **이미 보유 중인 종목**: 제외

## 3단계: 기술적 검증 (technicalFilter.ts)

TEBURN 시그널을 2차로 검증합니다. 주도주 점수가 높아도 기술적으로 위험한 타이밍이면 진입하지 않습니다.

### RSI (Relative Strength Index) 필터

```
RSI > 75 (과매수) → ❌ 진입 보류
  "이미 너무 올라서 물릴 위험이 높다"

RSI < 25 (과매도) → ✅ 통과 (반등 기대)
  "과하게 빠져서 반등 가능성"

25 ≤ RSI ≤ 75 → ✅ 통과 (정상 범위)
```

### 이동평균선(MA) 필터

```
MA5 > MA20 (단기 > 장기) → ✅ 상승 추세
  "최근 5일 평균이 20일 평균 위에 있다 = 올라가는 중"

MA5 < MA20 (단기 < 장기) → ❌ 하락 추세
  "최근 흐름이 꺾이고 있다 = 진입 위험"
```

### 데이터 소스

- KIS Open API의 일봉 차트 (최근 60일)
- 종목별로 일봉 조회 → RSI, SMA 계산

## 4단계: 매매 실행 (kisTrader.ts)

모든 필터를 통과한 종목에 대해 KIS Open API로 주문을 넣습니다.

### 매수 흐름

```
1. 실시간가 재확인  → getStockPrice(stockCode)
2. 매수 수량 계산   → 투자금(50만원) ÷ 현재가 = 수량
3. 시장가 매수 주문  → TTTC0802U (실투자) / VTTC0802U (모의투자)
4. 포지션 등록      → 진입가, 수량, 매수사유 기록
5. 텔레그램 알림
```

### 매도 흐름

```
1. 현재가 조회
2. 손익 계산 (현재가 vs 진입가)
3. 조건 충족 시 시장가 매도 → TTTC0801U / VTTC0801U
4. 포지션 제거
5. 실현 손익 기록
6. 텔레그램 알림
```

## 5단계: 리스크 관리 (riskManager.ts)

매 사이클(5분)마다 보유 포지션을 모니터링합니다.

### 청산 규칙

| 규칙 | 조건 | 액션 |
|------|------|------|
| 🛑 손절 | 현재가 ≤ 진입가 × (1 - 3%) | 즉시 시장가 매도 |
| 🎯 익절 | 현재가 ≥ 진입가 × (1 + 7%) | 즉시 시장가 매도 |
| 📉 트레일링 스탑 | 고점 대비 -2% 하락 (수익 구간) | 즉시 시장가 매도 |
| 🔔 장 마감 청산 | 15:10 도달 (선택 옵션) | 전 종목 시장가 매도 |

### 진입 제한

| 규칙 | 조건 |
|------|------|
| 최대 포지션 수 | 동시 3종목까지 |
| 일일 손실 한도 | 실현 손실 10만원 도달 시 신규 매매 중단 |
| 장외시간 | 09:05 ~ 15:15 외에는 매매 안 함 |

## 6단계: 알림 (notifier.ts → 텔레그램)

| 이벤트 | 내용 |
|--------|------|
| 봇 시작 | 설정값 요약 (등급, 투자금, 손절/익절 등) |
| 매수 | 종목명, 가격, 수량, 주도주 점수, 매수 사유 |
| 매도 | 청산 사유(손절/익절), 손익금액, 수익률 |
| 일일 요약 | 총 손익, 승률, 보유 포지션 현황 |
| 에러 | 에러 메시지 |

## 배포 구조

### Railway 프로젝트 (TEBURN)

```
Railway 프로젝트
├── 서비스 1: server    ← 기존 Express API (이미 배포됨, :4000)
├── 서비스 2: bot       ← 🆕 자동매매봇 + 대시보드 (:3001)
└── MongoDB             ← 기존 DB (공유)
```

- **server**: 기존 TEBURN API 서버. 주도주 점수 산출, 뉴스/테마 크롤링
- **bot**: 자동매매 봇. 매매 루프 + 모니터링 대시보드를 한 프로세스에서 실행
- **MongoDB**: 기존 TEBURN DB를 그대로 공유 가능

### 내부 통신

```
bot → server.railway.internal:4000/api/leading/hot   (Railway 내부 네트워크)
bot → openapi.koreainvestment.com                    (KIS 주문/시세 API)
bot → api.telegram.org                               (텔레그램 알림)
```

### 비용

- 봇은 5분에 한번 API 몇 번 호출하는 수준 → 월 $2~3 예상

### 프론트엔드 (Vercel)

- teburn.com은 Vercel에서 그대로 운영
- 봇과 직접 관련 없음 (변경 불필요)
- 나중에 대시보드 페이지를 클라이언트에 추가 가능

## 하루 타임라인

| 시각 | 이벤트 |
|------|--------|
| 08:00 | 봇 시작, KIS 토큰 발급, 기존 잔고 동기화 |
| 09:00 | 장 개시 (봇은 아직 대기) |
| **09:05** | **매매 시작** — 시초가 변동 5분 회피 후 첫 사이클 |
| 09:05~ | 5분마다: TEBURN 시그널 조회 → 기술적 필터 → 매수 판단 |
| 09:05~ | 5분마다: 보유 포지션 손절/익절 체크 |
| 15:10 | (선택) 전량 청산 — 오버나잇 리스크 제거 |
| 15:15 | 매매 종료 — 장외시간 대기 모드 |
| **15:40** | **일일 요약 알림 발송** |
| 15:40~ | 다음 장 개시까지 대기 |

### 5분마다 반복되는 매매 사이클

```
1. 보유 포지션 현재가 조회 → 손절/익절 조건 체크 → 해당 시 자동 매도
2. TEBURN /api/leading/hot 호출 → S등급 주도주 수신
3. 이미 보유 중인 종목 제외, 포지션 한도(3개) 체크
4. 후보 종목별 KIS 일봉 조회 → RSI/MA 기술적 필터 적용
5. 필터 통과 종목 → 실시간가 확인 → 시장가 매수 주문
6. 텔레그램 매수/매도 알림 발송
7. 대시보드 상태 갱신
```

## 설정값 요약

### 매매 전략

| 설정 | 기본값 | 설명 |
|------|--------|------|
| MIN_GRADE | S | 최소 주도주 등급 |
| MIN_HOTNESS_SCORE | 70 | 최소 주도주 점수 |
| MIN_CHANGE_RATE | 4% | 최소 등락률 |
| MAX_CHANGE_RATE | 25% | 최대 등락률 (고점 추격 방지) |
| RSI_OVERBOUGHT | 75 | RSI 과매수 기준 |
| MA_FAST / SLOW | 5 / 20 | 이동평균선 기간 |

### 리스크 관리

| 설정 | 기본값 | 설명 |
|------|--------|------|
| MAX_POSITIONS | 3 | 동시 보유 최대 종목 수 |
| POSITION_SIZE_KRW | 50만원 | 1종목당 투자금 |
| STOP_LOSS_PERCENT | 3% | 손절 기준 |
| TAKE_PROFIT_PERCENT | 7% | 익절 기준 |
| DAILY_LOSS_LIMIT_KRW | 10만원 | 일일 최대 손실 → 초과 시 매매 중단 |
